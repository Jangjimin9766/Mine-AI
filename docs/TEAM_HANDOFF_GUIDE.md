# 팀장 전달용 핸드오프 가이드 (Mine-AI)

## 1) 이번 작업에서 **완료된 범위**
- 매거진 생성 프롬프트를 HTML 중심에서 **Markdown 중심**으로 전환했습니다.
  - 문단 `text` 필드가 Markdown을 사용하도록 명시
  - `>`, `-`/`1.`, `**bold**` 스타일 가이드 추가
  - 기존 핵심 제약(3문단, 600~800자, 태그 whitelist, 이미지 키워드 규칙)은 유지
- 생성 오케스트레이터(`magazine_maker`)의 사용자 프롬프트도 Markdown 지침으로 맞췄습니다.
- 신규 유저 피드 초기화를 위해 **5명 × 3개 = 총 15개 매거진** 자동 생성 스크립트를 추가했습니다.
  - 결과 JSON 파일 저장
  - 선택적으로 Mine-server 내부 벌크 API 업로드 지원

## 2) 아직 남아있는 범위(팀 간 협업 필요)
- 프런트엔드가 Markdown 렌더링으로 전환되기 전까지는, 화면에서 줄바꿈/리스트/인용이 기대대로 보이지 않을 수 있습니다.
- Mine-server에서 벌크 삽입 엔드포인트를 실제로 받을 URL/인증 스펙이 확정되어야 자동 업로드를 바로 붙일 수 있습니다.

## 3) 오늘 자정까지 팀장에게 전달하면 되는 것
아래 4개를 전달하면 충분합니다.

1. **PR 제목/요약**
   - "매거진 본문 Markdown 전환 + 초기 더미 15건 생성 스크립트 추가"
2. **변경 파일 목록**
   - `app/core/prompts.py`
   - `app/core/magazine_maker.py`
   - `app/models/magazine.py`
   - `tools/generate_initial_dummy_data.py`
3. **실행 방법(더미 생성)**
   - `python tools/generate_initial_dummy_data.py`
   - 선택: `MINE_SERVER_BULK_URL`, `MINE_SERVER_BEARER_TOKEN` 설정 시 Mine-server 업로드까지 수행
4. **리스크/후속작업 한 줄**
   - "프론트 Markdown 렌더러 반영 후 화면 QA 필요"

## 4) 팀장에게 설명할 때 바로 쓸 수 있는 문구
- "토큰 효율을 위해 HTML 태그를 줄이고 Markdown 기반으로 생성되도록 바꿨습니다."
- "기존 매거진 품질 규칙(문단 수/길이/태그/이미지 규칙)은 유지해서 안정성은 지켰습니다."
- "신규 유저 온보딩용으로 5계정×3콘텐츠(15개) 자동 생성 스크립트를 넣어 피드 공백을 줄였습니다."
- "프론트가 Markdown 렌더링 반영되면 시각적 효과(인용/리스트/강조)가 제대로 노출됩니다."

## 5) 피그마/프론트 확인이 꼭 필요한가?
- **백엔드 작업만으로는 필수는 아닙니다.**
- 다만, Markdown 전환은 최종적으로 프론트 렌더링과 맞물리므로 최소한 아래 2가지는 확인 요청이 필요합니다.
  1) 어떤 Markdown 문법까지 지원할지 (`>`, 리스트, 볼드)
  2) 본문 영역 줄간격/목록 스타일이 디자인 가이드와 맞는지

즉, "지금 당장 피그마 픽셀단위 검수"는 필수 아님.
대신 **Markdown 렌더링 스펙 합의 + 간단 QA 일정 합의**는 꼭 필요합니다.
